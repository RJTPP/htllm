**htllm 1.0.0** is the first public release: a private AI chat that runs in your
browser. Run a model in the browser or on your own server; your chats and files stay
on this device.

- **Use it:** <https://htllm.rjtpp.com>
- **Offline:** download `htllm-v1.0.0.zip` below, unzip it, and serve the folder with
  any static server (for example `npx serve`). Give it an origin of its own, such as its
  own port or subdomain.

## Highlights

- **No backend:** no account, no telemetry. Chats, files, libraries and keys are stored
  only in your browser.
- **Models:** in-browser models (WebGPU), or LM Studio, Ollama, OpenRouter and any
  OpenAI-compatible server.
- **Chat and Workspace:**
  - Chat is plain conversation, with optional cited RAG over a library.
  - In Workspace, a tool-capable model reads your uploads and libraries, cites lines,
    writes versioned notes, and hands you files as cards.
- **Small, safe functions:** a calculator, CSV queries, and short JavaScript programs in
  a sandbox with no network.
- **MCP tools** over HTTP, with approval for every call.

See the [changelog](https://github.com/RJTPP/htllm/blob/main/CHANGELOG.md) for the full
list.

## Requirements

- Chrome or Edge, recent versions.
- **For in-browser models:** WebGPU and enough GPU memory for the model.
- **For your own server:** it must allow requests from the app's origin (CORS).
  - LM Studio: turn on CORS in the server settings.
  - Ollama: start it with `OLLAMA_ORIGINS=*`.
  - Chrome may ask to allow access to your local network.

## Known limitations

- **Browsers:** Firefox and Safari aren't tested yet.
- **Model servers:** only LM Studio (with Gemma 4) was checked live. Ollama, vLLM and
  cloud endpoints should work but aren't verified. See
  [compatibility](https://github.com/RJTPP/htllm/blob/main/docs/compatibility.md).
- **Workspace needs an HTTP model that can call tools.** In-browser models are limited
  to Chat.
- **Native OpenAI and Anthropic APIs don't allow browser requests (CORS).** Use an
  OpenAI-compatible gateway.
- **Answer quality depends on the model:**
  - Smaller models make more tool and citation mistakes; in the baseline evaluation,
    Gemma 4 often left research answers uncited.
  - Automatic RAG can miss part of a question that spans several sections.
- **Data:**
  - There is no sync between devices; use export and import.
  - Clearing the site's data deletes everything.
  - Storage is limited by the browser's quota.
- **Files:** PDFs need a text layer (no OCR), and Office files aren't supported. HTML and
  SVG files are shown as code, not rendered.
- **MCP:** servers must allow CORS for the app's origin, and the Docker MCP gateway
  doesn't yet. Only HTTP servers are supported; the app can't launch local (stdio) ones.
